# Copy me exactly

> **Not recommended.** This setup grew to fit how I work, and much of it will not fit you. Read the [guide](../guide/README.md), then add one tool at a time when you notice you need it. This page is here for completeness, and for anyone who wants to start from a known-good copy and remove things.

It installs public sources only. My own private skills and config are not here; where they belong, the step says so and links the kit page, so you can write your own.

The main path is Windows 11 with WSL2 (Ubuntu). At the end there is an optional section for an always-on agent on a Linux home server, and a box for people with access to a GPU cluster.

## What you need first

| Account or app | Cost | Needed for |
| --- | --- | --- |
| A Claude plan that includes Claude Code | Paid | Everything. I use an organisation plan through work. |
| GitHub | Free | Cloning plugins and skills, and a private repo for your vault. |
| Obsidian | Free | Reading and editing the vault. Any Markdown editor works. |
| Tailscale | Free tier | Only the optional home-server section. |

Remote Control (optional section) is off by default on Team and Enterprise plans until an organisation owner turns it on.

## Main path: Windows 11 and WSL2

### 1. Install WSL2 and Ubuntu

In PowerShell, as administrator:

```powershell
wsl --install -d Ubuntu
```

Restart if asked, open Ubuntu from the Start menu, and create your Linux user. Every command from here on runs in the Ubuntu terminal unless it says otherwise. I use Windows Terminal, which comes with Windows 11.

### 2. Base packages

```bash
sudo apt update
sudo apt install -y curl git unzip python3 python3-pip nodejs npm gh
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
gh auth login
```

`gh auth login` asks a few questions; pick GitHub.com, HTTPS, and log in with a browser.

### 3. Claude Code

```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version
claude
```

The first `claude` run asks you to log in with your Claude account. Then type `/exit`.

Run the installer inside Ubuntu, not in PowerShell. Node is not needed for Claude Code itself; the `nodejs` package above is for `npx` in later steps.

### 4. The always-on plugins: ponytail and caveman

```bash
claude plugin marketplace add DietrichGebert/ponytail
claude plugin install ponytail@ponytail
claude plugin marketplace add JuliusBrussee/caveman
claude plugin install caveman@caveman
```

Both load at every session start through their own hooks. See [ponytail](../kit/ponytail.md) and [caveman](../kit/caveman.md).

### 5. Matt Pocock's skills

```bash
claude plugin marketplace add mattpocock/skills
claude plugin install mattpocock-skills@mattpocock
```

This gives you [grilling](../kit/grilling.md) and [tdd](../kit/tdd.md), among others.

### 6. rtk

```bash
curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh
rtk init -g
rtk gain
```

`rtk init -g` adds the `PreToolUse` hook to `~/.claude/settings.json`. `rtk gain` should show a savings dashboard. If it says "command not found", or shows something else, you have a different program called rtk; see [rtk](../kit/rtk.md).

### 7. herdr

```bash
curl -fsSL https://herdr.dev/install.sh | sh
herdr integration install claude
```

The second command writes `~/.claude/hooks/herdr-agent-state.sh` and registers it in `~/.claude/settings.json`. Start herdr with `herdr`. See [herdr](../kit/herdr.md) for how I lay out workspaces.

### 8. graphify

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv tool install graphifyy
graphify install
```

The package has two y's; the command has one. If `graphify` is not found, run `uv tool update-shell` and open a new terminal. Then, in each repo where you want the graph kept up to date:

```bash
graphify hook install
```

I run graphify from the Windows side, with a small wrapper in WSL. A plain WSL install, as above, is simpler. See [graphify](../kit/graphify.md).

### 9. The vault

The vault is a folder of Markdown files in its own git repo. Mine lives on the Windows drive so Obsidian on Windows can open it, and WSL reaches it under `/mnt/c/`.

```bash
mkdir -p /mnt/c/Code/Obsidian
cd /mnt/c/Code/Obsidian
git init -b main
echo "# Vault" > README.md
git add README.md && git commit -m "Start vault"
gh repo create my-vault --private --source . --push
```

Open the folder in Obsidian (Windows) with "Open folder as vault". The [vault memory](../guide/03-vault-memory.md) page explains the layout I use.

### 10. get-up-to-speed and save-state

```bash
npx skills add mbarnfield63/claude-state-skills
```

This installs both skills into `~/.claude/skills/`. For each project:

1. Copy `MyProject_state.md` and `MyProject Log.md` from the [templates folder](https://github.com/mbarnfield63/claude-state-skills/tree/main/templates) into the vault, renamed for your project.
2. Paste `CLAUDE-snippet.md` from the same folder into the project's `CLAUDE.md`, and change the paths to those two files.

So that save-state can commit and push without asking each time, add this to `~/.claude/settings.json`, with your vault path:

```json
"permissions": {
  "allow": [
    "Bash(git -C /mnt/c/Code/Obsidian status:*)",
    "Bash(git -C /mnt/c/Code/Obsidian add:*)",
    "Bash(git -C /mnt/c/Code/Obsidian commit:*)",
    "Bash(git -C /mnt/c/Code/Obsidian push:*)",
    "Bash(git -C /mnt/c/Code/Obsidian diff:*)",
    "Bash(git -C /mnt/c/Code/Obsidian log:*)"
  ]
}
```

See [get-up-to-speed](../kit/get-up-to-speed.md) and [save-state](../kit/save-state.md).

### 11. Your global CLAUDE.md

`~/.claude/CLAUDE.md` holds the rules every session loads. Mine is private. It has a few lines on git commit messages and imports the rtk note with `@RTK.md`. Write your own, starting small; the [CLAUDE.md and skills](../guide/02-claude-md-and-skills.md) page explains what goes in it.

### 12. Occasional extras

I use these now and then. Skip them unless you need them.

```bash
# brag: turns a project website into a short launch video
claude plugin marketplace add latent-spaces/brag
claude plugin install brag@brag

# HyperFrames video skills
npx skills add heygen-com/hyperframes

# chrome-devtools MCP server: lets the agent inspect pages in Chrome
claude mcp add chrome-devtools --scope user -- npx -y chrome-devtools-mcp@latest
```

My own occasional skills (`tikz-figures`, `socratic-tutor`, `to-prd`, `to-issues`, `writing-great-skills`) are private. The [kit index](../kit/README.md) says what each does, if you want to write your own.

### Check it worked

Start `claude` in any project folder. You should see the ponytail and caveman rules load at the start, and replies should be short. Run a shell command through the agent and its output should come back condensed by rtk. Type `/get-up-to-speed` in a project you set up in step 10; it should brief you from the state file.

## Optional: an always-on agent on a home server

I keep one agent, VaultAgent, running all the time in a copy of my vault on a small Ubuntu server at home. I reach it from my phone through [Remote Control](../kit/remote-control.md). You do not need this for anything else on this page.

### 13. Claude Code and the vault on the server

On the server, as your normal user:

```bash
sudo apt install -y curl git tmux gh
curl -fsSL https://claude.ai/install.sh | bash
gh auth login
gh repo clone my-vault ~/obsidian
cd ~/obsidian && claude
```

Log in, then `/exit`. Repeat steps 4 to 7 here if you want the same plugins on the server.

### 14. Keep the session running

A systemd user service starts the session in tmux and restarts it if it stops. Save this as `~/.config/systemd/user/vaultagent.service`:

```ini
[Unit]
Description=VaultAgent (Claude Code with Remote Control)
After=network-online.target

[Service]
Type=forking
Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin
WorkingDirectory=%h/obsidian
ExecStart=/usr/bin/tmux new-session -d -s vaultagent "%h/.local/bin/claude --remote-control vaultagent"
ExecStop=/usr/bin/tmux kill-session -t vaultagent
Restart=on-failure

[Install]
WantedBy=default.target
```

Then:

```bash
systemctl --user daemon-reload
systemctl --user enable --now vaultagent.service
sudo loginctl enable-linger "$USER"
```

`enable-linger` keeps the service running when you are not logged in, and starts it at boot. `tmux attach -t vaultagent` shows the session on the server itself. The session should now appear as "vaultagent" in the Claude app and at claude.ai/code.

The vault on the server and the vault on your PC are two clones of one repo, so pull and push on both sides. save-state pushes after every save, which keeps them close.

### 15. Tailscale (optional)

Remote Control does not need it. Tailscale is useful for reaching the server over SSH from anywhere without opening ports. Install it on the server and your PC from [tailscale.com/download](https://tailscale.com/download), log in on both, and use the server's Tailscale name with `ssh`.
